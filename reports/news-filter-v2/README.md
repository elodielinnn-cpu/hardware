# 新闻筛选 V2：本地对照与人工复核入口

日期：2026-11-20。正式仓库为 `elodielinnn-cpu/hardware`，生产入口是 `NEWS_FILTER_MODE=v3` 的 `scripts/fetch_real_sources.mjs`。本报告对应本地试跑，**没有发布到网站，也没有云端验证**。

## 这次改了什么

统一标签、启用范围与四种首页准入路径见 `config/news-screening-rules-v2.mjs`，可读规则见 `config/news-screening-rules-v2.md`。抓取先记录输入是否有正文，再从摘要和正文分别提取事实；每个候选事件单独做业务映射和首页判断。证据不足显示“未知/待复核”，不自动写成“低/无事件”。保留七类事件标签和原有阶段体系，3C 不在启用范围。

旧版结果不能覆盖 V3 判断。单篇分类失败会保留为待复核；业务知识库加载失败或整批来源没有可用新闻时，本轮更新报错并保留上次数据。正文预算由每轮 80 条提高到 200 条，单来源上限仍为 60 条。来源 403、正文无效和其他失败均记录，不编造正文。

同一事件允许相邻句补阶段证据；评测结论和产品成熟阶段分开。对“CPO”缩写增加光学语境要求，避免把高管头衔当成共封装光学产品。关键企业的可归因财务结果、明确供应链行动和具体工程结论可独立进入管理价值判断。财报同一公司、同一指标、同一金额且报道日期相近时，仅隐藏重复的首页卡片，仍保留两篇于全集。

## 仍需判断

- 70 条仅摘要且无法支持完整结论的新闻需要补证据，尤其来源详情 403 和 SEC 文件仅有元数据的情况；它们不是 70 条确定的低价值新闻。
- 当前只对明确的同一财务指标跨来源重复做首页合并；其他产品/部署跨来源事件组仍需继续校验。
- 这次没有新一轮人工真值，不能宣称误入率、漏入率已下降，也没有逐篇 AI 模型与程序的公平对比。
- 最新完整抓取使用临时正文缓存和实时 RSS；云端运行后应检查 Actions 产物中的 `ruleVersion`、`inputStatus`、`candidateDecisions`，再复核首页。
