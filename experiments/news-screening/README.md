# 新闻筛选试跑

复用现有业务知识表，独立抓取五个来源并输出三类结果。运行 `node experiments/news-screening/run.mjs`，结果位于 `outputs/news-screening/latest.csv` 和 `latest.json`。使用 `--replay` 可基于保存的正文重新筛选，保留原始抓取时间。运行 `node experiments/news-screening/test.mjs` 检查代表性规则。

本入口供抓取与筛选试验使用，目前未接入云端定时任务或网站数据。业务表仍为待审核草稿。规则判断属于候选筛选，不能证明原报道已获独立核实，也不能证明立讯与报道对象存在供货关系。

正文优先提取 `.post-content`（9to5Mac、Electrek）与 `#paragraph`（IT之家），再使用 article/main 容器。匹配嵌套容器的结束位置，避免侧栏推荐卡片覆盖正文。无法识别的页面进入待定，验证页面、内容不足和请求失败分别记录。使用 `--refetch` 重新抓取保存批次的原始链接，保持候选集合和原始抓取时间，逐篇记录正文抓取时间。促销、软件及娱乐标题可直接排除。业务对象和事件需在同段出现，配置罗列不会仅因产品名称而入选。需求与供应链事件保留独立入口，避免强制要求零件词。CSV 保留正文状态、容器、字数、错误、事件、证据和规则版本，JSON 保留正文以便复查。

当前限制包括跨媒体事件去重尚未实现、正文提取覆盖有限、词义与否定句识别有限。抓取时间与来源发布时间分别保存，旧报道不会被改写为今日发布。
