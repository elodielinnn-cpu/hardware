# 通信与数据中心、汽车新闻筛选试跑

本入口只处理通信与数据中心、汽车。消费电子来源和产品匹配已移除，消费电子主导的报道从结果文件中剔除。共享业务知识表通过 `scope.mjs` 限定到这两个业务，PPT 第 3、4 页补充的范围逐项保留材料出处。产品范围不代表立讯与新闻中的企业存在供货关系，也不代表产品已量产。

运行 `node experiments/news-screening/run.mjs` 抓取当前批次。`--replay` 使用保存的证据重算，`--refetch` 重抓保存批次的链接。结果位于 `outputs/news-screening/latest.csv` 和 `latest.json`。运行 `node experiments/news-screening/test.mjs` 验证正反例。

## 筛选逻辑

1. 识别原文具体变化，包括供应商、合作、订单产能、并购投资、需求成本、技术制造、部署供货、平台方案和供应风险。一般配置、教程、背景回顾不通过。标题和摘要提供候选线索，入选需要正文或有足够内容的 RSS 原文节选支持。
2. 核对业务关系。直接路径核对变化对象是否对应产品或制造环节。间接路径要求上游对象发生变化，另有原句明确说明对具体产品的影响。影响句可以在后续段落，但需要提及同一上游对象，或与事件紧邻且有指代。只提品牌、只有财报总数、汽车零售促销、只有芯片性能而无具体影响，均不能直接入选。
3. 产品线索与事件关系未明、间接影响仍属推测、抓取证据不足的保留待定。原文事实和规则推导分别记录。

`rules.mjs` 维护事件与内容规则，`scope.mjs` 维护业务范围与产品别名，`screen.mjs` 执行事件识别和业务核对。关系允许同段紧邻的明确指代，不会把文章其他位置出现的零件词自动拼接成相关性。

## 来源和提取

当前来源为 ServeTheHome、StorageReview、Electrek、DCD、ADAS & Autonomous Vehicle International。每源最多 20 条候选，每批最多 5 个正文请求。正文优先识别 `.post-content`、`.entry-content` 和 `#paragraph`，再使用 article/main。段落提取与筛选均排除上下篇推荐文本。

网页请求失败时，如果 RSS 本身提供至少 250 字的原文段落，可以使用该节选完成判断。记录为 `rss_evidence`，证据来源标记为 `rss_excerpt`，并保留网页错误和抓取状态，不把它标为全文抓取成功。RSS 中的标题和短摘要不会替代这些段落。DCD 请求失败或返回验证页时记录来源告警，其余来源继续运行。

结果保留变化识别状态、业务核对状态、关系类型、变化原句、影响原句、对应产品和范围依据。JSON 另保留所有候选变化、正文证据、来源失败和剔除数量。抓取时间、正文请求时间与来源发布时间分别记录。

## 验证范围与限制

回归用例覆盖直接产品变化、跨段明确上下游影响、无影响依据的芯片变化、无关对象共现、否定、传闻、软件教程、消费电子隔离和推荐链接污染。实际抓取后需抽查入选与排除案例，不能用入选数量证明准确率。

当前使用规则识别，复杂指代、因果方向、否定范围、不同时间事件及隐含关系仍可能误判或漏判。知识表仍为草稿，PPT 是产品范围依据。移动通信细分产品的覆盖有限。跨媒体同一事件的语义去重尚未实现。本入口处于试跑阶段，尚未接入云端定时任务和网站发布。

## 人工检验和失败诊断

执行步骤、复杂因果检查表和指标定义见 [AUDIT.md](AUDIT.md)。`audit.mjs prepare` 冻结当前原文与系统结果并生成待标注 CSV，`audit.mjs score <批次目录>` 将人工结论与冻结版本、当前规则进行比较。人工标签由审阅人填写。

`diagnose.mjs` 复查失败来源的 RSS、主页和正文响应。正常抓取入口复用 `fetch.mjs`，将 HTTP 状态、验证页、DNS、超时、403 和 429 分别记录。详细响应信息位于 `sourceDiagnostics` 和各条新闻的 `webFetchDiagnostics`。
