# 新闻筛选试跑

复用现有业务知识表，独立抓取五个来源并输出三类结果。运行 `node experiments/news-screening/run.mjs`，结果位于 `outputs/news-screening/latest.csv` 和 `latest.json`。使用 `--replay` 可基于保存的正文重新筛选，保留原始抓取时间。运行 `node experiments/news-screening/test.mjs` 检查代表性规则。

本入口供抓取与筛选试验使用，目前未接入云端定时任务或网站数据。业务表仍为待审核草稿。规则判断属于候选筛选，不能证明原报道已获独立核实，也不能证明立讯与报道对象存在供货关系。

正文优先提取 `.post-content`（9to5Mac、Electrek）与 `#paragraph`（IT之家），再使用 article/main 容器。使用 `--refetch` 重抓保存批次的链接，使用 `--replay` 仅重算筛选结果，两者保留原始抓取时间。

筛选按两步执行。

1. 从正文句子和分句识别供应商变化、订单产能、并购投资、需求成本、技术制造和供应风险。一般发布、配置罗列、供应商背景介绍不构成变化。标题和摘要仅提供待核对线索。
2. 核对变化对象与业务范围的对应。使用变化分句的产品信息，或同段紧邻前句的显式指代。客户名称、终端名称、文章其他位置的零件词不能单独放行。业务线索存在但绑定不明确、上游间接关系、摄像头主体边界未确认或消息不确定时保留待定。

`rules.mjs` 单独维护事件类型、产品别名和消费电子试用范围。结构件、显示模组、天线无线模组、SMT/FATP 来自用户提供的前序对话，标为 `conversation_working_scope`，尚待业务负责人审核。其他产品沿用知识表，摄像头模组不会因此改为已核实直接业务。三大业务使用相同流程。

CSV 和 JSON 保留变化识别状态、业务核对状态、变化原句、业务依据原句及对应产品。JSON 另保留所有候选变化，产品记录包含关系和业务范围依据。入选理由说明变化类型与对应产品。规则版本为 `event-then-business-v2`。

当前限制包括跨媒体事件去重尚未实现、正文提取覆盖有限、词义、指代和否定句识别有限，跨段实体关系可能漏判，句内复杂修饰仍可能误判。抓取时间与来源发布时间分别保存，旧报道不会被改写为今日发布。
