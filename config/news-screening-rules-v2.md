# 新闻筛选统一口径 V2（运行规范）

生效范围：`hardware` 仓库的 `NEWS_FILTER_MODE=v3` 云端更新及本仓库离线回放。人工原稿为 `NEWS_FILTER_GENERAL_RULES_V2.md`；本文件记录已落实的运行结构和仍需验证的边界，不把旧个案当成白名单。

## 唯一入口与数据顺序

`scripts/fetch_real_sources.mjs` 收集、清洗和标记输入状态；`experiments/unified-tagging.mjs` 从可用文本抽候选事件；`experiments/news-filter-v3/business-profile.mjs` 按 `config/luxshare-business-profile.json` 映射业务；`experiments/news-filter-v3/news-filter-v3.mjs` 对每个候选分别判断证据、相关性、重要性和首页路径，再选展示主事件。公开标签、启用范围和路径 ID 统一定义于 `config/news-screening-rules-v2.mjs`。之后云端 Gemini 对少量已入选和接近门槛的候选复核首页去向与主事件；复核结果须通过事件编号、证据引文及内容哈希核对才在下次更新应用。

不使用标题、来源或历史复核编号白名单。关键词仅发现候选和显式风险；不能证明立讯与新闻主体存在供应关系。旧版打分仍用于对照和非 V3 模式，云端 V3 的单篇分类失败会标为待复核，不回退为旧版结论。V3 整体配置失败时停止本次更新，保留网站上次成功数据。

## 内容与展示分层

1. **输入**：全文可用、仅摘要可用、正文抓取失败或详情未处理。短公告只要足以证明当前结论即可；无法从摘要确定的事件或业务关系标为待补证据，不能自动写成低相关、低重要。网页正文失败不将导航或评论冒充证据。
2. **事实**：抽主体、对象、动作、阶段及引文。候选不受首页展示数量限制，按事件分别评价。工程结论可以独立成为候选，不要求新品发布。
3. **标签**：行业为通信与数据中心、汽车电子；消费电子/3C 不在本项目启用范围。事件固定七类：新技术、新产品、商业合作、订单与定点、投资与产能、经营变化、政策与风险。阶段为已发布、试验验证、初步应用、规模应用、计划中；未明确或不适用不展示。可订购是内部可用性事实，不另增公开标签。
4. **业务**：直接产品、上游/相邻的具体影响、战略企业的实质经营变化分开判断。新闻无需点名立讯，但必须能说明对已确认业务或重要战略角色的影响。只命中 CPU/GPU/SSD、企业名或“AI 平台”等词不足以证明管理价值。
5. **首页内容**：证据足够、启用范围内、非传闻、相关性和重要性均至少为中，且落入产品技术变化、关键企业经营战略变化、产业需求成本风险、实质工程分析中的一个路径。阶段只描述进度，不作为统一放行门槛。没有固定首页数量。
6. **展示**：日期窗口、事件去重和排序与内容准入分开；超出窗口或重复不能改写为“低价值”。

## 审核输出

云端 `v3Audit` 保存规则版本、业务知识库版本/哈希、输入状态、详情失败原因、候选事件判断、业务匹配、证据充分性、拒绝码和准入路径。`relevance=未知` / `importance=未知` 表示输入未能支持判断。公开正文只保留用于核查的有限引文，不发布抓取全文。

## 仍需验证

- 程序层仍依赖文本模式和知识库；云端模型只复核少量程序候选，无法补回来源发现和正文抽取前已丢失的新闻。复杂主体指代、跨段因果和影响链条仍可能误判，须继续抽查。
- SEC 申报当前主要使用元数据，未普遍读取附件中的具体事项；这类记录的缺证据状态不等于申报没有重要事项。
- RSS 不提供的旧报道可能在来源发现阶段缺失。发布结果不能单独证明是来源、截取、抓取或去重哪一步造成。
- 事件级跨来源去重、同一产品跨日期进展判别仍需专门回放。当前 URL/标题去重不等于完整事件组去重。
